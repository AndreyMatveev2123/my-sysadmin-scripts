# Сборщик логов в контейнере перед Nginx с HTTPS (Капстоун-проект)

Скрипт читает `/var/log/syslog`, отбирает строки со словами error и fail и записывает их в `report.txt`. В рамках ДЗ2 скрипт упакован в Docker-контейнер, который отдаёт отчёт по HTTP на порту 8080. Перед контейнером стоит Nginx в роли reverse proxy с HTTPS (самоподписанный сертификат), порт 80 перенаправляет запросы на HTTPS кодом 301. Контейнер запускается и перезапускается как служба systemd (`my-app.service`), поэтому стартует автоматически при загрузке сервера.

В репозитории находятся: `script.sh` (сам скрипт), Dockerfile (образ на ubuntu:22.04 с Python 3 для встроенного веб-сервера на порту 8080), `docker-compose.yml` (запуск через Compose с томом `/var/log` только для чтения), `nginx-my-app.conf` (конфиг Nginx), `my-app.service` (unit-файл systemd) и `sample_output.txt` (пример вывода скрипта).

Для запуска нужно собрать образ командой `docker build -t my-script .` и запустить контейнер командой `docker run -d -p 8080:8080 --name my-app -v /var/log:/var/log:ro my-script`. Том с логами обязателен, без него отчёт будет пустым. Для HTTPS создаётся самоподписанный сертификат командой `openssl req -x509 -nodes -days 365 -newkey rsa:2048` с указанием путей `/etc/ssl/private/my-app.key и /etc/ssl/certs/my-app.crt`, после чего конфиг копируется в `/etc/nginx/sites-available/my-app`, включается ссылкой в sites-enabled, стандартный сайт default удаляется, а конфигурация проверяется командой `nginx -t` и применяется через `systemctl reload nginx`. Для запуска как службы контейнер создаётся командой `docker create` с теми же параметрами порта и тома, unit-файл копируется в `/etc/systemd/system`, затем выполняются `daemon-reload`, `enable` и `start`.

Проверка работы: `curl -kI https://127.0.0.1/` возвращает 200, `curl -I http://127.0.0.1/` возвращает 301, `systemctl status my-app` показывает active (running), а `systemctl is-enabled my-app` возвращает enabled. Логи смотрятся командами `journalctl -u my-app -f` (журнал службы) и `tail -f /var/log/nginx/access.lo`g (журнал доступа Nginx): один и тот же запрос фиксируется в обоих журналах независимо.

В рамках Части 1 на сервере собран учебный стенд: три файла по 512 МБ подключены как loop-устройства, из двух собран RAID 1 (`/dev/md0`, смонтирован в `/mnt/raid`), на третьем создан LVM (группа vg_data, том lv_logs на 200 МБ, смонтирован в `/mnt/logs`). Состояние проверяется командами `cat /proc/mdstat`, `df -h`, `pvs`, `vgs` и `lvs`. Loop-устройства не переживают перезагрузку сервера.

Приватный ключ сертификата в репозиторий не включён и создаётся на сервере отдельно. Сертификат самоподписанный, поэтому браузер показывает предупреждение, для учебного стенда это ожидаемо.

Для полного подъёма проекта с нуля предназначен скрипт `bootstrap.sh` в корне репозитория: `./bootstrap.sh`. Он собирает образ и создаёт контейнер, поднимает RAID 1 и LVM на loop-устройствах, настраивает Nginx с самоподписанным сертификатом и регистрирует службу systemd, после чего сам проверяет доступность сервиса. Скрипт безопасен при повторном запуске: если RAID уже собран, он ничего не пересоздаёт, а если после перезагрузки остались файлы-образы дисков в `/mnt/raid-lab`, он подключает их заново и собирает массив без потери данных. Если сервис не отвечает за 30 секунд, скрипт завершается с ошибкой. Выбран вариант А («Сборщик логов»): контейнеру нужен том `/var/log`, иначе отчёт `report.txt` будет пустым, при этом HTTP-ответ всё равно будет 200, поэтому проверять нужно именно содержимое отчёта. Ограничения: скрипт ищет слова error и fail по всему тексту, поэтому в отчёт попадают и безобидные строки, например отладочные сообщения с пустым полем error=. Встроенный веб-сервер Python предназначен только для учебной среды. Сертификат самоподписанный, браузер покажет предупреждение.
